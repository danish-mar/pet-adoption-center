Relational Schema & 3NF Normalization Analysis

The database adheres to Third Normal Form (3NF) and Boyce-Codd Normal Form (BCNF): every non-prime attribute is fully functionally dependent on candidate keys with no transitive dependencies.

1. shelters 3NF OK
PK: (id) • Candidate Keys: {name}

FD: {id} → {name, address, city, state, capacity, phone, created_at}

2. users 3NF OK
PK: (id) • Candidate Keys: {username}, {email}

FD: {id} → {username, password_hash, salt, role, full_name, email, phone}
FD: {username} → {id, ...} | {email} → {id, ...}

3. pets 3NF OK
PK: (id) • FK: shelter_id → shelters(id)

FD: {id} → {shelter_id, name, species, breed, age_years, gender, size, status, fee, ...}

4. adoption_applications 3NF OK
PK: (id) • FKs: pet_id → pets(id), user_id → users(id)

FD: {id} → {pet_id, user_id, applicant_name, living_space, status, reviewer_notes}
